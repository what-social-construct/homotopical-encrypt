## Immediate shared commitment/projection profile

The user has identified the existing cochain commitments and their actual
projection as central to Paper 3's contribution. Start from that existing
object, not a replacement commitment. The
[source trace](../../docs/COCHAIN_PROXIMITY_TRACE.md) records the proved path.

The selected construction uses the actual systematic RS interpolation
coefficients, lifted to integers, as the head restriction of a two-vertex,
one-edge cellular sheaf. Its source valid locus is intrinsic modular
exactness: an actual integral opening and an integer carry satisfy
`delta0 a = z + q*m`. A complete coordinate codec reads the same original
payload into scalar cochain coordinates and integer plane pairs.

Each metric keeps its native normalization: cochain edits count `2n` scalar
positions; plane and RS edits count `n` whole pairs. The proved generic bridge
is `d_cochain ≤ d_plane = d_RS ≤ 2*d_cochain`. Modular validity is saturated
under `q`-shifts, and explicit representative lifts prove the plane/RS
distance equality for all integer inputs. The source metric is not defined
as a pullback. The existing near interface can use the explicit calibrated
score `2*d_cochain`; the native far implication has no factor loss.

The paired monomial `X^k` gives a capacity-far family in these modular metrics.
Its actual canonical `q=12289`, `n=4096`, `k=1024` payload adapter, same-artifact
join and restricted fixed-mix specialization now pass focused checks. The
expanded aggregate and consolidated dependency checks pass; artifact details remain centrally recorded. For diagonal
pairs, every challenge other than `-1` is good and the bad fraction is exactly
`1/q`. For arbitrary capacity-far pairs a fixed nonzero mix can cancel, so a
general protocol must bind the pair before sampling or authenticate a proved
restricted line profile.

This profile is separate from `Context.decodedDistance`, the frame score and
the full HCP residual. A no-wrap integer-syndrome profile gives only a coarse
Euclidean first-shell result. A nonempty positive far region concerns raw
received inputs; accepted exact anchors have zero native distance under this
declared compatible interpretation. Broader deployed or hidden-Hodge source
identifications, and all cryptographic games, remain separate obligations.
The generic tasks Q04--Q07 are complete; Q08 tracks this concrete adapter and
scope/validation closure rather than restarting those coding proofs.

## Selected bounded central claim

The first concrete endpoint is one conservative owned-resource transition
from the original before-state and trusted sheaf interpretation to its computed
successor. The [owned-resource kernel](../../lean/Protocol/Ledger/OwnedResource.lean)
fixes a catalog of natural-number IDs, owners, assets and strictly positive
amounts. It consumes one unit of an input ID, creates one unit of a distinct
absent and unspent output ID of the same asset/amount, and uses `[inputId]` as
its nullifier list. Unit multiplicities and absence of active spent IDs are
preserved; the consumed ID cannot be spent again or resurrected as a later
output. The positive mechanical fixture has value seven and retains supplied
header coordinates, without fake authentication facts.

[Transfer.Owned](../../lean/Protocol/Transfer/Owned.lean) constructs the actual
action, snapshot and proposal from these data and the original storage context.
Successful structural and packet checking derives `Candidate.Valid` and
`AcceptedUpdate`; candidate validity is not a premise of the operational
checker. The signature verifier and exact-payload proof verifier have supplied
indexed soundness contracts. The latter is bound to the actual trusted payload
interpretation, not every decoder sharing a public tag. Catalog/policy and
metadata identifiers select trusted meanings; their names alone prove no
arithmetization, cryptographic or context correctness.

The owner authorizes the pre-proof [typed intent](../../lean/Protocol/Evidence/TransferTranscript.lean),
including its signing domain, transfer, original public context, prepared draft
and manifest root. Actual metadata, owner-signature bytes and proof bytes are
included in the complete evidence packet. State-content hashing excludes the
current tip/evidence coordinates; the original before-evidence root is included
explicitly in the intent, alongside the parent-tip coordinate. Later
proposal/block/evidence coordinates complete the state and are bound by the
final complete signed proposal. This acyclic typed construction proves no
global hash injectivity or new cryptographic security theorem.

The [semantic envelope adapter](../../lean/Protocol/Evidence/TransferEnvelope.lean)
packages independently derived validity using the actual candidate/transfer
witness, public intent and original artifact. It does not derive new verifier
soundness from TCB statement equality. The [anchored adapter](../../lean/Protocol/Transfer/Anchored.lean)
reuses the same candidate, payload interpretation, artifact and exact
[one-input manifest](../../lean/Protocol/Storage/TransferManifest.lean).
A supplied matching acceptance quorum signs the same final proposal; it is a
conditional certification endpoint, not finality. Backend persistence still
requires an actual matching receipt.

This action holds the ledger snapshot and epoch fixed. It is not a ledger
rotation, topology migration, atomic backend update or six-stage proximity-gate
completion. The generic resource kernel remains available independently of
this bounded public-ID profile; no global account/UTXO architecture, anonymous
nullifier construction, mint/burn policy or new commitment/MAC primitive is
selected. Production codecs/hashes/signatures/proofs, state-origin security,
adaptive security games and runtime refinement remain separate work.

### One-shot sampled integrity and the actual release

[Transfer.PublicView](../../lean/Protocol/Transfer/PublicView.lean) projects the
actual canonical packet bytes, parsed packet, complete final proposal and
original one-input manifest view from the same checked transfer. Coherence
theorems retain its original public context/payload, exact metadata and intent,
ordered input directory, signed manifest root and action-derived singleton
nullifier. Resource input/output/signer identifiers and verifier metadata are
observable. Changed exposed identifiers distinguish these records; an explicit
input-ID equality test separates different inputs without private Hodge data.
The record is one transfer release. Public setup, prior-state and catalog
access, auxiliary information and network/access metadata must be declared
separately by an experiment.

[TransferCheck](../../lean/Protocol/Evidence/TransferCheck.lean) and
[Transfer.Operational](../../lean/Protocol/Transfer/Operational.lean) retain the
same actual parser, canonical-byte and metadata/intent checks and the selected
Boolean verifier algorithms, without assuming their universal semantic
soundness. Local authorization and exact-payload acceptance under the actual
trusted interpretation suffice to derive the same candidate validity and
computed update. An operationally accepted invalid candidate therefore entails
either signature acceptance of an unauthorized exact intent or proof acceptance
of a payload rejected by that interpretation. These are predicates on the
actual attempted packet, not assumed abstract success relations.

[Transfer.Security](../../lean/Protocol/Transfer/Security.lean) supplies a
fixed-setup one-shot experiment: the adversary receives a specified transfer
release and explicit auxiliary input, uses a tape sampled from a supplied
`PMF`, and returns one transfer/byte attempt. The accepted-invalid probability
is at most the sum of authorization-failure and payload-failure probabilities
for that same experiment. Supplied primitive budgets compose by this bound;
support-local absence of both failures gives probability zero. No independence
is needed. `ofCheckedRelease` instantiates the observation with an existing
checked transfer's exact projection; the attacked configuration remains an
explicit separate input.

No numerical or negligible primitive bound, efficient adversary class,
security parameter, adaptive signing/proving oracle or corruption experiment
is supplied. The authorization event is not an EUF-CMA definition. Public-root
lookup, trusted state origin, cryptographic bytes, runtime refinement,
persistence and finality remain separate obligations. Neither this integrity
bound nor equality of a selected `(class,b)` pair proves complete-view hiding,
sender anonymity or anonymous-nullifier security.
