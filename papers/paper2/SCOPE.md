## Immediate shared commitment/projection profile

The user has identified the existing cochain commitments and their actual
projection as central to Paper 3's contribution. Start from that existing
object, not a replacement commitment. The
[source trace](../../docs/COCHAIN_PROXIMITY_TRACE.md) records the proved path.

The selected construction uses the actual systematic RS interpolation
coefficients, lifted to integers, as the head restriction of a two-vertex,
one-edge cellular sheaf. Its source valid locus is intrinsic modular
exactness: an actual integral opening and an integer carry satisfy
`delta0 a = z + q*m`. A complete coordinate codec reads the same original
payload into scalar cochain coordinates and integer plane pairs.

Each metric keeps its native normalization: cochain edits count `2n` scalar
positions; plane and RS edits count `n` whole pairs. The proved generic bridge
is `d_cochain ≤ d_plane = d_RS ≤ 2*d_cochain`. Modular validity is saturated
under `q`-shifts, and explicit representative lifts prove the plane/RS
distance equality for all integer inputs. The source metric is not defined
as a pullback. The existing near interface can use the explicit calibrated
score `2*d_cochain`; the native far implication has no factor loss.

The paired monomial `X^k` gives a capacity-far family in these modular metrics.
Its actual canonical `q=12289`, `n=4096`, `k=1024` payload adapter, same-artifact
join and restricted fixed-mix specialization now pass focused checks. The
expanded aggregate and consolidated dependency checks pass; artifact details remain centrally recorded. For diagonal
pairs, every challenge other than `-1` is good and the bad fraction is exactly
`1/q`. For arbitrary capacity-far pairs a fixed nonzero mix can cancel, so a
general protocol must bind the pair before sampling or authenticate a proved
restricted line profile.

This profile is separate from `Context.decodedDistance`, the frame score and
the full HCP residual. A no-wrap integer-syndrome profile gives only a coarse
Euclidean first-shell result. A nonempty positive far region concerns raw
received inputs; accepted exact anchors have zero native distance under this
declared compatible interpretation. Broader deployed or hidden-Hodge source
identifications, and all cryptographic games, remain separate obligations.
The generic tasks Q04--Q07 are complete; Q08 tracks this concrete adapter and
scope/validation closure rather than restarting those coding proofs.

## Proposed central claim

Complete one end-to-end proof-carrying transition: from a committed public
state and one fully bound candidate to its computed accepted after-state.

The proposed theorem schema is: under the explicitly stated authentication,
hash/commitment, and proof-system assumptions, verifier acceptance for that
candidate implies the specified valid transition, with matching context and
roots, exact value-flow conservation, and fresh nullifiers consumed once.
Cryptographic error and adversary access must be part of the statement.
Acceptance here is local transition validity; finality requires a separate
consensus theorem. The conditional mathematical core of this schema now has
typed state/action, candidate-indexed TCB evidence, conservation/replay
endpoints and a same-proposal quorum adapter. The secure-protocol claim still
requires a concrete profile, security games and runtime refinement.

Resources, assets and nullifiers remain abstract. The first action uses finite
nonnegative resource markings and an explicit additive asset valuation,
choosing neither accounts nor UTXOs. It is conservative; fees may be included
among produced resources. Mint/burn, ownership/authorization and cryptographic
nullifier derivation need their own selected profile. A small positive-value
transfer fixture exercises this kernel without claiming production security.

The mathematical joins previously missing from the first-action core now
have source implementations. Their assumptions remain visible: `Policy`
supplies authorization, additive valuation and snapshot interpretation;
`RootBindings` supplies authentication/inclusion relations on the actual
objects; its evidence-root relation currently includes the public hashed
cochain artifact, not the full serialized proof or verifier metadata.
Full proof-evidence inclusion remains profile work. A concrete root scheme
must also specify an acyclic preimage order: the computed successor includes
the block digest and proposal roots, so hashing the entire proposal and
successor into one another is not an implementation of these relations.
TCB acceptance uses its stated verification contracts. The replay
endpoint excludes reuse of the same nonempty action list, not every alternate
encoding of a spend without a nullifier-derivation theorem.

The storage objects likewise retain explicit assumptions. Their context fixes
the original sheaf interpretation, snapshot, payload and artifact; roots name
different objects rather than being forced equal. A sealed manifest is an
exact complete list with a supplied root relation. Durability is a separate
receipt contract, and the local consumed state cannot advance again. This
does not choose a real backend, prevent reinitializing a second history with
the same run ID, or prove atomic disk/ledger application and physical erasure.

The new `TransitionAnchor` source reuses the candidate's actual snapshot and
original public artifact by equality, then authenticates its exact sealed list
and manifest root through `HistoryBindings`. `ProjectionAnchor` retains the
existing final nested prefix and joins its actual gate database to the
candidate's evidence root under a separate supplied inclusion relation. This
does not replace the open serialized-proof/verifier metadata inclusion work.
The wire profile can bind the manifest in an authenticated block body or add a
dedicated root coordinate; neither encoding is selected by this adapter.
`AnchorExamples` exercises a positive transfer, matching quorum and persistence
receipt, with rejected run/snapshot/nonexact-input substitutions. Their Lean 4.35
builds and selected standard-only theorem-dependency audits pass; see the shared register. All these adapters
hold the cell complex `X` and sheaf `F` fixed. The separate ephemeral rotation
layer now relates actual source/target sheaves over that same `X`, transports
the full samples and derives payload-decoder migration from their original
bindings. It does not atomically migrate a sealed history, update the base
topology or supply the cryptographic channel and retirement policy.

The source metrics remain separate. `Context.decodedDistance` measures the
decoded payload's Euclidean distance to exactness; it vanishes for the HCP
adapter's accepted exact component. `Sheaf/ObservationQuotient.lean` instead
uses the existing `HodgeEncryptedCochain` sample's kernel-normalized Laplacian residual.
Its coexact-ray obstruction excludes a global positive far theorem through
the exact-component view on the unrestricted carrier when a nonzero coexact
direction exists. A quotient-aware, authenticated or noise-bounded profile
must state which residual it preserves. Controlled-lift theorems do not
silently identify these two source models.

This is a bounded conservative mathematical endpoint; its completed local
builds and theorem-dependency checks are recorded in the shared register.
It does not complete the secure Paper 2 protocol. Full blockchain, storage
lifecycle and Rust completion are not prerequisites for Paper 3's bounded
commitment/projection radius analysis.
